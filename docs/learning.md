- 深入理解了一个test例子: test_file_hashes.py中的test_mutation_discards_first_digest_and_retries_once函数
  - authorized函数由于是@pytest.fixture，在被其它函数当作参数时，会自动调用并获取authorized函数的返回值，而不是把它在下面当作一个函数对象使用
  - 内部嵌套函数change_after_read是对scan._read_sha256函数的一个包装。_read_sha256是程序计算完哈希到再次检查读取后状态中间的一个环节，这个包装的目的是让此次扫描在计算哈希后且检查读后状态前更新文件内容，以让读后检查发现变化并重新开始计算哈希。
  - calls[]是用来让此次扫描文件第一次的时候更改文件，第二次重试就不更改文件了因为要让扫描成功通过
  - monkeypatch是暂时将此次测试中的scan._read_sha256函数替换为change_after_read这个包装过的函数
  - sleep是一个列表是因为此测试并不要真的暂停一秒然后再重新计算哈希，而是在该暂停一秒的地方给sleep列表加一个元素1，以表示“按理来说”程序在这里会暂停一秒
- 理解了数据库中idempotency表的意义：此表用来阻止同一份申请生成两份后端任务。
  - 1. 前端生成申请编号X，后端受理并且返回任务编号A
  - 2. 前端如果因为网络或其它原因没有获取到任务编号A，那就无法得知后端是否受理成功，此时前端如果再申请的话，会用同一份申请编号X来申请而不是把点击按钮当作一次全新的申请操作。此时后端如果判断上次已经有一样的申请了，那就不会新建一个任务。
- change_lock和_submission_lock都是程序内部的线程锁，分别保护两个环节：
  - submission_lock检查重复的扫描申请
  - change_lock是只允许一个线程进行scan_root()也就是真正的后台扫描操作 (观察文件，协调identity，更新数据库). 此lock在当前阶段是多余的，因为现在每次接单后只有一个扫描工作线程
- 除了正式流程的扫描以及更改数据库意外，代码保留了A1第二步和第三步的独立检查功能，分别通过--metadata-only、--verify-content 主动调用。这两个功能分别用来检查根目录下文件的元数据和哈希值但不登记到数据库。
