## D01 项目名称

用户最新确认产品名称为 FileMind；现有仓库及代码目录保持 FileMindDemo，沿用原业务阶段和安全协议。不因产品命名调整另建项目或重命名目录。手册旧产品名需统一为 FileMind，代码目录示例使用 FileMindDemo。

## D02 Python 开发环境

当前虚拟环境使用 Python 3.13，依赖记录在 `requirements.lock.txt`。手册建议 3.11/3.12，用户此前选择了 3.13；保留当前选择，不为文字一致性重建环境。锁文件不等于跨 Python 版本兼容证明，其他版本支持需另行验证。

## D03 Vue 页面与同源部署

用户要求迁移到 Vue；现用 Vue 3、Element Plus 和 Vite，替代原生页面逻辑。Element Plus 对应 Vue 3。前端构建到 `app/static/dist`，由 FastAPI 提供；不单独部署前端服务器，不为开发页面开放 CORS。

代价是增加 Node 工具链，首次运行及页面测试前必须构建。源码与 npm 锁文件提交 Git，node_modules、构建产物与本机工具不提交。修改后可使用构建 watch，并手动刷新页面。

2026-11-03 修正扫描根选择框的样式遗漏：组件样式按需导入，新增 ElSelect 时也须在前端入口导入 select/style/css，该入口会一并加载选项、弹层和滚动区域样式。遗漏会使选中名称、箭头与选项脱离正常布局；补官方样式，不通过隐藏这些内部元素修复，也不更改根授权与扫描协议。

## D04 安全策略兼容组件布局

Element Plus 使用运行时内联样式，现有 CSP 允许 `style-src 'self' 'unsafe-inline'`。脚本仍只允许 self，不允许内联脚本或 unsafe-eval；不能为组件兼容性随意扩大脚本或连接来源。

## D05 端口与启动入口

固定使用手册 A0 验收端口 8765，Host/Origin 精确匹配 `127.0.0.1:8765`，不把 localhost 当作等价白名单。

保留项目 CLI 和直接 Uvicorn 两种入口，共用应用生命周期与锁。CLI 承担额外配置参数、固定服务器选项及阶段重载限制；直接 Uvicorn 要按文档约定传 host/port。两者服务逻辑相同，不代表所有启动选项都一样。

## D06 应用数据目录

当前默认 DATA_DIR 为仓库下 `data`，已加入 Git 忽略。手册第 30 章建议 `.localdata`，保留现有名称。A1 第一步已在配置与根登记中校验数据目录不在资料根内，避免索引自身。

ROOT_PATH 默认未授权，A0 启动无需真实资料目录。后续使用独立人工样例，不把源码仓库整目录作为待扫描资料。

## D07 先保留只读与 Mock

当前无真实模型或执行器；已有只读元数据、哈希检查与显式身份同步入库。页面标签和配置字段不证明其他功能已实现。先完成 A 的只读链路再讨论 B；不提前接入付费 API、云上传或文件写入。评测、并发与恢复结论只引用实际证据。

## D08 A1 第一步的最小数据库与样例 2026-11-02

仅创建 roots/files，PRAGMA user_version=1 是当前 schema version；后续表和迁移随阶段增加。连接开启外键、WAL 和有限 busy_timeout，CLI 与服务共享数据目录锁，服务只核验已有数据库，不自动初始化或重置未知版本。

样例 manifest 需要真实 file_id，因此生成器为自己创建的文件分配 UUID 并登记为 discovered。sha256 仍为 NULL，不实现任意目录扫描或提前计算哈希。D01/D06 两个 UUID 不同，字节相同；后续扫描应按已有路径协调，不重发 ID。

使用已安装的 pypdf 生成手册指定的两页英文 PDF，并验证实际文本可提取；无需新增 ReportLab。英文 Base14 字体不需要中文字体嵌入；若以后增加中文 PDF 样例，必须另做字体与提取验证。

根外随机哨兵在被忽略的 demo_docs_boundary，内层链接使用相对路径，避免把用户绝对路径写入 Git。大小写冲突仅记录计划候选；不在 Mac 上强行创建大小写同名文件。对中途意外失败保留现场，不自动清理重试。

目录策略根据名称、应用包后缀和设备号排除常见系统/云目录与跨设备入口；不能据此证明所有第三方同步目录都被自动识别。安全范围仍是本机单用户、无恶意并发路径替换。

新规则使旧重载测试中的 DATA_DIR 位于资料根内这一夹具无效；将资料放到独立 documents 子目录，保留重载参数与配置值断言。新增独立失败测试继续要求这种嵌套配置被拒绝。

## D09 A1 第二步先收集观察值，不提前协调身份 2026-11-02

第二步只完成普通文件的扩展名过滤与 lstat 元数据收集。FileMetadata 是不可变观察记录，不含 file_id/sha256；MetadataReport 在完整完成后才返回。名称相同、内容相同都不合并候选。完整入库留到稳定性和身份规则实现后，避免把单次观察误当成可靠索引。

复用目录边界迭代器，每个目录另用 os.scandir 列出候选；对当前 500 文件规模优先保持职责易懂，暂不优化合并两次目录枚举。后续若基于实测优化，保留边界测试。

root_id 只选择登记记录，不能凭它读取旧授权：只读数据库查询必须与本次本机 ROOT_PATH、设备号一致且启用。CLI 共享数据目录锁，不修改数据库行；锁文件和 SQLite 自身的运行辅助文件不属于资料内容。

MAX_FILES 超限或任何遍历/stat 错误时，当前不返回部分成功、不标 missing。范围级 unavailable 与持久扫描记录留到步骤 5；这会暂时降低容错性，但不会误删或掩盖不完整扫描。

用户已给 DOCX 样例添加“无保修条款”，基线测试仍期待旧文导致 1 failed/47 passed。本轮将精确内容断言同步为新文本，保留段落与正文检查，不删除或放宽断言。

## D10 A1 第三步采用稳定读取报告 2026-11-02

保留默认 metadata_only 行为，显式 --verify-content 才读字节、分块 SHA256。不开启模型，不提取文字，不改变 file_id、数据库或 manifest。使用 Python 标准库 hashlib，无新依赖。

读取块为 1MiB；签名包含设备号、inode、大小、mtime_ns、ctime_ns，并校验总字节数和最终路径。1 秒重试间隔是实现参数，手册要求延迟重试但未指定秒数。测试注入 sleep 回调，真实 CLI 使用 time.sleep，不靠长时间等待制造竞态。

不只用 stat 后普通 open：逐层 dir_fd/O_NOFOLLOW，最终 O_NONBLOCK，读取前 fstat，读后安全重开复核路径。这样拒绝链接替换和 FIFO 阻塞；仍承认单用户边界及检查后变化的限制，不将其宣传为安全隔离或原子快照。

默认 20MiB 来自手册规模上限，CLI 提供 --max-file-mib 调整入口。超限标 too_large；IO 或路径失败标 failed；两次观察到变化标 unstable。后三者无 digest，不作为索引输入。complete=false 与非零退出码明确提示未全部成功，保留稳定结果供诊断。

第三步交付时 unstable 只记录在报告，样例数据库中 sha256 仍为 NULL。第四步已增加身份同步，见 D11；第五步持久扫描报告见 D12。只能将稳定结果送入身份协调，哈希不能替代 UUID。

A1 文档沿用用户改名后的 `A1 Steps.md`，统一追加第三步并修复旧名称链接，不新建分步骤说明。

## D11 A1 第四步显式同步与保守身份推断 2026-11-02

增加 --sync，而不让已有只读命令暗中写库。纯身份计划函数与文件系统观察、SQL 提交分离：路径优先；缺失路径与新路径的 dev/ino/sha256 唯一匹配才推断改名。当前 st_nlink 必须为 1，避免根外硬链接也引起歧义；不按哈希合并副本。missing 历史再次同名出现分配新 UUID，不靠名称复活身份。此前 seed_demo 预分配的 UUID 首次同步保留，NULL 哈希补基线而不增加版本。

同路径内容变化增加 content_rev、置 stale，防止将来复用旧解析结果；唯一改名只增加 path_rev。应用数据库更新不等于修改资料，WRITE_ENABLED=false 下允许显式同步；不更改 manifest。

持有进程锁，读完并复核观察后生成计划，短 SQL 事务校验根授权与旧行快照，整批提交或回滚。不把整段哈希放进写事务。第五步完成前，任何观察不完整或旧路径未能可靠判定都整批拒绝；不提前实现部分成功、unavailable 范围记录或 UI。复核降低普通并发变化风险，但不是整个文件系统的原子快照，也不防御同账号恶意进程。

## D12 A1 第五步按成功范围确认缺失 2026-11-02

正式 scan_root 为每个成功完整枚举的目录保存精确名字集合，失败时丢弃该目录的枚举证据。仅在成功父目录中缺少相应项且路径安全复核仍消失时标 missing；失败范围旧行 unavailable，正常兄弟范围继续。不把文件读取失败、策略排除或符号链接替换当删除。单文件故障单独隐藏，MAX_FILES 超限、提交前变化或数据库快照冲突仍整批不应用。

保留旧行最后已知哈希以便恢复后识别内容版本；失败报告不提供可用 digest，后续检索必须同时验证状态与版本，不能仅看 sha256 非空。新失败项保留 UUID 和错误状态，too_large 映射数据库 unsupported。A2 解析另做，空/损坏 PDF 在 A1 哈希成功不代表其正文可用。

对齐手册第 8 章默认 CLI 扫描验收：不带模式开关即正式扫描，--sync 为别名；原元数据查看改为显式 --metadata-only，--verify-content 保留严格哈希检查。此前 CLI 测试只调整选择只读模式的参数，原只读断言保留；当时暂留第四步严格函数，后续按 D13 清理。

最小接入附录 24 的扫描任务协议：POST 返回 202 job_id，GET 只读任务/最近报告；Idempotency-Key 保证重复请求复用，同键异参 409，单任务容量 429。一个后台线程与应用变更锁串行扫描，不增加定时器或 A4 增量队列。A1 始终完整哈希，verify_content=false 也不会跳过初始身份校验；报告明确有效模式。

schema 2 迁移仅新增 jobs/idempotency，保留原文件身份。成功/部分成功报告与文件更改同事务，异常回滚后另记失败；重启未完成任务标 interrupted，不自动重放。GET 使用只读连接。扫描日志存在被忽略的 DATA_DIR 数据库，不另外输出私人正文或 token。

核查旧 Uvicorn 入口测试时发现：它仅把进程锁重定向到临时目录，应用配置仍捕获默认 DATA_DIR；新增任务管理器会使该测试触碰实际数据。因此同时隔离数据库检查与管理器启动，保留精确导入入口及鉴权断言。新增故障测试以回调注入权限错误，不调用 chmod。

## D13 删除废弃入口，身份测试只验证正式流程 2026-11-04

用户要求删除正式流程不用的废弃函数，并迁移仍有意义的测试。移除第四步 sync_file_identities、其专用 IdentitySyncReport 和内嵌的拒绝报告函数；移除从未接入运行流程的 Settings.authorized_path。根授权、逐层目录验证和安全文件打开仍由正式流程实现，不删除实际安全检查。

文件身份测试改为直接调用 scan_root：保留 UUID、版本、改名、副本、硬链接、清单、授权、锁、来源变化与数据库并发变化断言。旧版“单文件超限必须整批不写”改为验证超限隔离且正常范围可确认缺失；链接替换改为验证 unavailable、编号保留、没有误标 missing。旧权限异常和 SQL 回滚两个重复测试删除，正式范围测试已有更完整的恢复/报告覆盖，不削弱这些安全要求。

元数据查看、严格哈希查看和目录遍历仍由受支持的 CLI 模式调用，应用工厂、路由和回调也是有效入口，不因它们不在网页扫描路径就删除。不新增兼容包装层或新模式，避免继续维持两套扫描逻辑。
